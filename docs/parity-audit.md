# Toolport+ parity coverage audit

Date: 2026-10-04, refreshed by MIG-CLN-11 on `mig/MIG-CLN-11` (stacked on `b7296dcf`, MIG-CLN-8). First written 2026-10-03 at `djody/main` `fc59de1`. Every wiring item the first audit proposed has landed (MIG-CMP-3, MIG-AUTH-6, MIG-AUTH-7, MIG-CTX-9, MIG-PRF-1, MIG-DIR-1, MIG-SKL-7 to MIG-SKL-11, MIG-OBS-3, MIG-SELF-7, MIG-CUT-4); the rows below name the tests that now cover each of them, and the gaps that remain say why.

This audit walks every parity-matrix row whose decision is PORT, EXTEND or CHANGE (DROP and pure REUSE rows are out of scope; B1-04 and B1-05 are "REUSE; CHANGE names" and are included). For each row it records how production code is reached and which named test exercises that path. Behaviour is checked only to the depth of "this code path exists and is exercised by that test".

Reachability means at least one of:

- `ctl`: a `toolportctl` command in `src-tauri/src/plus/ctl/` (the `COMMANDS` table).
- `ipc`: a `plus.*` handler in the `HANDLERS` table of `src-tauri/src/plus/mod.rs` (reached through `plus_invoke`).
- `selfmcp`: a tool or resource of the `toolport-selfmcp` binary (`src-tauri/src/plus/selfmcp/`).
- `gw`: the gateway path (stdio proxy, profile scope, daemon).
- `ui`: a mounted component under `src/plus/` or a call from the settings view.

Test totals after the cleanup: `env -u TOOLPORT_SECRET_KEY cargo test --no-default-features --lib --bins --tests --no-fail-fast` gives 3530 passed, 0 failed, 9 ignored (the first audit counted 2833 passed on its base). The nine ignored tests are `oauth_lock_child_process`, `plus::sync::engine_tests::regenerate_rust_golden`, `secrets::tests::set_get_delete_round_trip`, two live catalog tests and four `teams_activation` tests. The `one_gateway_conformance` suite counts mock processes host-wide, so it must run alone when another slot has a gateway daemon running (39 passed).

Method for the unreferenced-code list: a scratch copy of the tree with `pub mod plus` turned into `pub(crate) mod plus` and one entry function calling `dispatch`, `selfmcp::serve_stdio`, `ctl::run`, `auth::scheduler::tick` and `obs::otel_host::spawn`, then two passes. `cargo check --no-default-features --lib` reports every pub item that no production path reaches. `cargo check --no-default-features --lib --profile test` additionally reports what no unit test uses either. Integration tests compile the library without `cfg(test)`, so whatever `tests/` imports stays ungated.

Rows that were owned by in-flight items in the first audit ("in SKL-7") are now audited like the others.

## Wiring added by this audit

- `toolportctl usage [--root <dir>] [--no-refresh]` (`ctl/usage.rs`): a CLI surface for `plus.obs.summary`, closing the reachability gap of B1-18.
- `toolportctl mcp install [--profile <id>] / uninstall / doctor / tools` (`ctl/mcp.rs`, plus `selfmcp::register::{install, uninstall_self_server, find_self}`): the lifecycle commands of B7-09. `install --profile` registers and enables in one all-or-nothing registry write.

Both are covered by unit tests next to the code, by the `ctl_smoke` classification tests, and by the `hardening_leak` canary matrix.
