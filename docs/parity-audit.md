# Toolport+ parity coverage audit

Date: 2026-10-03. Audited at `djody/main` `fc59de1`; the branch is rebased on `491ab75`, which already carries the SKL-7 and CTX-8 merges. Their rows are listed as in SKL-7 and not re-audited.

This audit walks every parity-matrix row whose decision is PORT, EXTEND or CHANGE (DROP and pure REUSE rows are out of scope; B1-04 and B1-05 are "REUSE; CHANGE names" and are included). For each row it records how production code is reached and which named test exercises that path. Behaviour is checked only to the depth of "this code path exists and is exercised by that test".

Reachability means at least one of:

- `ctl`: a `toolportctl` command in `src-tauri/src/plus/ctl/` (the `COMMANDS` table).
- `ipc`: a `plus.*` handler in the `HANDLERS` table of `src-tauri/src/plus/mod.rs` (reached through `plus_invoke`).
- `selfmcp`: a tool or resource of the `toolport-selfmcp` binary (`src-tauri/src/plus/selfmcp/`).
- `gw`: the gateway path (stdio proxy, profile scope, daemon).
- `ui`: a mounted component under `src/plus/` or a call from the settings view.

Test totals before this audit: `cargo test --no-default-features --lib --bins --tests --no-fail-fast` gave 2833 passed, 0 failed, 9 ignored. The nine ignored tests are `oauth_lock_child_process`, `plus::sync::engine_tests::regenerate_rust_golden`, `secrets::tests::set_get_delete_round_trip`, two live catalog tests and four `teams_activation` tests. The `one_gateway_conformance` suite counts mock processes host-wide, so it must run alone when another slot has a gateway daemon running (39 passed). With the wiring below (12 new tests) the same command gives 2845 passed on the audited base and 2876 passed, 0 failed, 9 ignored after the rebase on `491ab75`.

Method for the unreferenced-code list: a scratch copy of the tree with `pub mod plus` turned into `pub(crate) mod plus` and one entry function calling `dispatch`, `selfmcp::serve_stdio` and `ctl::run`, then `cargo check --no-default-features --lib`. Every "never used" warning inside `plus/` is a pub item that no production path reaches.

Rows owned by in-flight items are marked "in SKL-7": the skills status, clean, uninstall and resolve wiring (B4-02, and the agents and styles status and clean parts of B4-05 to B4-08) is being wired there and is not touched here.

## Wiring added by this audit

- `toolportctl usage [--root <dir>] [--no-refresh]` (`ctl/usage.rs`): a CLI surface for `plus.obs.summary`, closing the reachability gap of B1-18.
- `toolportctl mcp install [--profile <id>] / uninstall / doctor / tools` (`ctl/mcp.rs`, plus `selfmcp::register::{install_self_server, uninstall_self_server, find_self}`): the lifecycle commands of B7-09. `install --profile` registers and enables in one all-or-nothing registry write.

Both are covered by unit tests next to the code, by the `ctl_smoke` classification tests, and by the `hardening_leak` canary matrix.
